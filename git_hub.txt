GIT E GITHUB - GUIA DE COMANDOS
================================

O VS Code e o GitHub podem ser usados juntos, mas sao coisas diferentes:

- O VS Code e o programa onde voce edita os arquivos.
- O Git controla as versoes do projeto na sua maquina.
- O GitHub guarda uma copia do repositorio na internet.
- O PowerShell e um lugar onde voce digita os comandos do Git.

Os comandos abaixo devem ser executados no terminal do VS Code ou em um
PowerShell aberto na pasta do projeto.

Para este exemplo, a pasta local e:

C:\Users\fabio\Downloads\teste\atividades-da-aula-

Para entrar nessa pasta pelo PowerShell:

cd "C:\Users\fabio\Downloads\teste\atividades-da-aula-"


1. CONECTAR A PASTA DO VS CODE AO GITHUB PELO GIT
=================================================

Esta e a configuracao inicial. Use estes comandos quando a pasta ainda
nao estiver conectada a um repositorio do GitHub.

1.1 Inicializar o Git na pasta
------------------------------

Cria um repositorio Git local dentro da pasta atual:

git init

Use "git init" apenas uma vez nessa pasta. Se ela ja tiver sido
inicializada, nao e necessario repetir.

1.2 Conferir os arquivos
------------------------

Mostra os arquivos novos ou modificados:

git status

1.3 Preparar os arquivos
------------------------

Adiciona todos os arquivos da pasta para o proximo commit:

git add .

Para adicionar somente um arquivo:

git add calculadora.py

Para adicionar uma pasta:

git add Atividade-Avaliativa

O comando "git add" ainda nao envia nada ao GitHub. Ele apenas prepara
os arquivos para serem salvos em uma versao.

1.4 Criar a primeira versao local
----------------------------------

Salva os arquivos preparados em um commit:

git commit -m "Primeiro commit"

Um commit e um registro de uma versao do projeto na maquina local.

1.5 Definir a branch principal
------------------------------

Define "main" como o nome da branch principal:

git branch -M main

1.6 Conectar ao repositorio do GitHub
--------------------------------------

Liga o repositorio local ao repositorio remoto no GitHub:

git remote add origin https://github.com/fabio-Sou/atividades-da-aula-.git

"origin" e apenas o nome curto usado para esse endereco do GitHub.

Confira se a conexao foi configurada:

git remote -v

Se aparecer a URL do repositorio em "fetch" e "push", a conexao esta
configurada.

1.7 Enviar a primeira versao para o GitHub
------------------------------------------

Envia a branch "main" pela primeira vez:

git push -u origin main

O parametro "-u" salva a associacao entre a branch local e a branch
remota. Depois disso, normalmente sera possivel usar apenas "git push".

Se aparecer erro 403, consulte a secao 7.


2. COMO SALVAR UMA PASTA NOVA NO GITHUB
=======================================

Se voce quer colocar uma pasta local nova no GitHub, siga esta sequencia
dentro da pasta que deseja salvar:

cd "CAMINHO-DA-PASTA"
git init
git add .
git commit -m "Adiciona projeto"
git branch -M main
git remote add origin URL-DO-REPOSITORIO-NO-GITHUB
git push -u origin main

Exemplo usado neste projeto:

cd "C:\Users\fabio\Downloads\teste\atividades-da-aula-"
git init
git add .
git commit -m "Adiciona atividades da aula"
git branch -M main
git remote add origin https://github.com/fabio-Sou/atividades-da-aula-.git
git push -u origin main

IMPORTANTE:
------------
Antes de usar "git remote add origin", confira se o repositorio remoto
ja existe:

git remote -v

Se "origin" ja aparecer, nao use "git remote add origin" novamente.
Nesse caso, a pasta ja esta conectada ao GitHub.


3. COMO CONTINUAR COM FUTURAS MODIFICACOES
==========================================

Sempre que voce alterar, criar ou excluir arquivos:

3.1 Ver o que mudou
-------------------

git status

3.2 Preparar as alteracoes
--------------------------

Para preparar tudo:

git add .

Para preparar somente arquivos escolhidos:

git add calculadora.py README.md

3.3 Criar uma nova versao
-------------------------

git commit -m "Descreva o que foi alterado"

Exemplos:

git commit -m "Corrige calculadora"
git commit -m "Adiciona exercicios do modulo 3"

3.4 Enviar a nova versao para o GitHub
--------------------------------------

git push

Fluxo completo para o uso diario:

git status
git add .
git commit -m "Descreva a alteracao"
git push

O comando "git add ." prepara os arquivos, "git commit" cria uma versao
local e "git push" envia essa versao para o GitHub.


4. COMO BAIXAR UMA PASTA QUE ESTA NO GITHUB
===========================================

4.1 Baixar pela primeira vez com clone
--------------------------------------

Use "git clone" quando quiser copiar um repositorio do GitHub para o
computador:

git clone https://github.com/fabio-Sou/atividades-da-aula-.git

Esse comando cria uma nova pasta com os arquivos e todo o historico de
versoes.

Para escolher outro nome para a pasta local:

git clone https://github.com/fabio-Sou/atividades-da-aula-.git nome-local

4.2 Atualizar uma copia que ja foi clonada
------------------------------------------

Entre na pasta clonada e baixe as alteracoes do GitHub:

cd "CAMINHO-DA-PASTA"
git pull

"git pull" combina duas acoes: baixa as alteracoes e atualiza os arquivos
locais.


5. COMO TIRAR ARQUIVOS OU PASTAS DO GITHUB
=========================================

5.1 Apagar do computador e do GitHub
-------------------------------------

Use "git rm" para apagar um arquivo ou uma pasta do projeto:

git rm nome-do-arquivo
git rm -r nome-da-pasta

Depois, crie a versao da remocao e envie:

git commit -m "Remove arquivos antigos"
git push

A remocao sera registrada no historico, e o arquivo deixara de aparecer
na versao atual do GitHub.

ATENCAO: "git rm -r" apaga a pasta e os arquivos do computador. Confira
o caminho antes de executar.

5.2 Tirar do GitHub, mas manter no computador
----------------------------------------------

Use este caso quando quer que um arquivo deixe de ser enviado ao GitHub,
mas continue existindo na pasta local:

git rm --cached nome-do-arquivo

Para uma pasta:

git rm -r --cached nome-da-pasta

Depois, salve a remocao:

git commit -m "Deixa arquivos somente locais"
git push

Para evitar que esses arquivos sejam adicionados novamente, coloque seus
nomes no arquivo ".gitignore".

5.3 Tirar o repositorio remoto da pasta local
---------------------------------------------

Este comando remove a conexao da pasta local com o GitHub. Ele nao apaga
o repositorio que ja esta no site:

git remote remove origin

Use somente se quiser desvincular a pasta local do repositorio remoto.

5.4 Apagar o repositorio inteiro do GitHub
------------------------------------------

Essa acao deve ser feita no site do GitHub, em:

Settings > Danger Zone > Delete this repository

E uma acao permanente. Apagar a pasta local ou usar "git remote remove"
nao apaga o repositorio do site.


6. COMO VER O VERSIONAMENTO
============================

6.1 Ver o historico no PowerShell
----------------------------------

Mostra os commits resumidos:

git log --oneline

Mostra o historico com mais detalhes:

git log

Mostra o que foi alterado no ultimo commit:

git show

Mostra as alteracoes que ainda nao foram preparadas:

git diff

Mostra as alteracoes que ja foram preparadas para o commit:

git diff --staged

6.2 Ver uma versao anterior
---------------------------

Lista os commits e seus identificadores:

git log --oneline

Para consultar um commit especifico:

git show ID-DO-COMMIT

Para ver como estava um arquivo em uma versao anterior:

git show ID-DO-COMMIT:nome-do-arquivo

Substitua "ID-DO-COMMIT" pelo identificador mostrado no "git log".

6.3 Desfazer alteracoes ainda nao salvas em commit
--------------------------------------------------

ATENCAO: este comando descarta as alteracoes locais do arquivo:

git restore nome-do-arquivo

Para tirar um arquivo da area de preparacao, sem apagar suas alteracoes:

git restore --staged nome-do-arquivo

Confira o resultado com:

git status

6.4 Ver o historico pelo site do GitHub
---------------------------------------

1. Abra o repositorio no GitHub.
2. Clique no nome do arquivo para ver seu conteudo.
3. Clique em "History" para ver as versoes desse arquivo.
4. Para ver todos os commits, abra a aba "commits".
5. Clique em um commit para ver exatamente o que foi adicionado,
   alterado ou removido.

Cada commit representa uma fotografia do projeto naquele momento. O
GitHub mostra quem criou a versao, quando ela foi criada e quais linhas
mudaram.


7. ERRO DE PERMISSAO 403
========================

Se aparecer:

Permission to fabio-Sou/atividades-da-aula-.git denied to fabio-cri

o repositorio pertence a "fabio-Sou", mas o Git esta tentando autenticar
como "fabio-cri".

O nome configurado nos commits nao e necessariamente a conta usada no
login. Para verificar a identidade dos commits:

git config --global user.name
git config --global user.email

Para corrigir as credenciais no Windows:

1. Abra o "Gerenciador de Credenciais".
2. Entre em "Credenciais do Windows".
3. Procure entradas relacionadas a "github.com" ou
   "git:https://github.com".
4. Remova a credencial da conta errada.
5. Execute novamente:

git push

6. Entre com a conta que possui permissao no repositorio.

Se o repositorio pertence a "fabio-Sou", a conta autenticada precisa ser
"fabio-Sou" ou uma conta que tenha sido adicionada como colaboradora.


8. COMANDOS DE CONSULTA IMPORTANTES
====================================

Ver em qual branch voce esta:

git branch --show-current

Ver os remotos configurados:

git remote -v

Trocar o endereco do remoto existente:

git remote set-url origin https://github.com/fabio-Sou/atividades-da-aula-.git

Ver os arquivos acompanhados pelo Git:

git ls-files

O nome correto do remoto e "origin", com "g". Nao use "origem":

git push -u origin main
